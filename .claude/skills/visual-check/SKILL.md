# 视觉回归比对

## 什么时候用

**该用**：改 SCSS / 设计 token、拆分组件、调整模板结构、升级 Element Plus
或 Vue —— 凡是"预期视觉不变"的改动，都该有基线兜底。

**不该用**：本来就要改外观的需求。那种情况下差异是预期的，跑了只会得到
一堆噪音。

## 前置

需要一个跑着的站点和一个能登录的账号。工具在 `web/`：

```bash
cd web
npm install          # 已包含 puppeteer-core / pixelmatch / pngjs
```

`puppeteer-core` 不自带浏览器，用的是本机装的 Chrome。路径不对时用
`TD_CHROME` 指定。

## 用法

```bash
cd web

# 1. 改动之前先建基线
TD_BASE=http://localhost:5173 TD_USER=admin TD_PASS=xxx \
  npm run visual:capture -- /tmp/vc-before

# 2. 改代码，构建

# 3. 再采一次
TD_BASE=http://localhost:5173 TD_USER=admin TD_PASS=xxx \
  npm run visual:capture -- /tmp/vc-after

# 4. 比对（退出码 0 通过，1 有回归）
npm run visual:diff -- /tmp/vc-before /tmp/vc-after --out /tmp/vc-diff
```

环境变量：`TD_BASE` 站点、`TD_API` 后端（默认同源）、`TD_USER`/`TD_PASS`
或 `TD_TOKEN`、`TD_ONLY` 只拍指定页面（逗号分隔）、`TD_ISSUE_KEY` /
`TD_PROJECT_KEY` 指定详情页取样对象（默认取列表第一条）、`TD_CHROME`。

取样页面在 `web/scripts/visual/pages.json`，按需增删。

## 怎么读结果

输出形如：

```
users-dark.png    19493 px  1.2183%  y≈840(2469px) y≈560(2192px)
```

`y≈840` 是差异最密集的行带。**先看行带，再去裁那一段图看内容**，比盯着
整页截图找快得多。加 `--out` 会输出差异图（红点标差异像素）。

## 三个必须知道的坑

**1. 噪声底不是零。** 页面里有随时间变化的内容（相对时间、SLA 剩余分钟、
表单里"当前时间"的默认值），同一份代码连跑两次也不会完全一致。

所以：**先跑两次基线，量出噪声底**，再决定阈值。本项目噪声底约
0.008%，默认阈值 0.02%。跳过这一步的话，你分不清 0.005% 是噪声还是回归。

**2. 尺寸变了先查数据，不是先查代码。** 报 `尺寸 1600x2192 → 1600x2322`
时，多半是页面内容变多了而不是样式变了。本项目踩过两次：冒烟测试发了
评论、加了工时，`activity_logs` 里留下记录把底部时间线撑高 —— 删评论和
工时删不掉活动记录，得单独清。

**跑完写操作的冒烟测试，务必还原数据再比对**，包括附带产生的活动日志。

**3. 差异超出噪声底就得看，不能当噪声放过。** 本项目遇到过 0.0328%
（噪声底的 4 倍），裁图一看是「指派人：告警机器人」变成「未指派」——
是还原数据时把 `assignee_id` 置成了 NULL，而原值不是 NULL。
0.03% 这种量级在整页截图上肉眼完全看不出来。

## 补充：光比像素不够

逐像素只证明"长得一样"，不证明"还能用"。拆分组件后 props/emit 链路断了、
事件没接上，截图可能完全一致。

**交互密集的区块，比对之外要单独跑一次端到端**：点按钮、看列表数量变化、
挂 `pageerror` 监听。本项目拆右侧信息栏时就是这么验的（关注 1→2、
取消关注 2→1、分配给我、编辑下拉出现）。
