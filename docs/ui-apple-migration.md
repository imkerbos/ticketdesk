## 0. 边界

**做**：视觉语言——字体、层级、间距、形状、材质、控件形态、状态层。

**不做**（本次改造范围外，要做另开需求）：

- 不改后端 API，不改业务逻辑，不删现有功能
- 不换技术栈，不引第二套图标库，不引 UI 框架
- 不把工单列表改成卡片流（**密度是产品要求，不是历史包袱**）
- Command Palette、全局快捷键属于新功能，不在这里做

**已经完成、不要重做**：设计 token 体系、elevation 归零、表格行高 44px、
行内操作悬停显隐、8 个列表页空态统一、报表页 `TdBarChart` + `--td-cat-*`。

## P0 · 令牌层

改这一层，收益自动传导到全部页面。**这是唯一必须先做完的阶段。**

| # | 任务 | 验证 |
|---|------|------|
| 0-1 | 写 `scripts/palette-check.mjs`，实现六项校验（明度带 / 彩度下限 / 色觉障碍相邻分离度 / 正常视力分离度 / 对比度 / 亮暗一致性），接到 `make palette-check` | 对**现有**色板跑一遍，必须六项全过 —— 过不了说明校验器写错了，不是色板错了 |
| 0-2 | 新增 `--td-font-sans`，`body` 与 Element Plus 变量一起接上 | 构建通过；工单列表截图对比，字形应可见变化 |
| 0-3 | 字阶按 §3.2 对齐；工单号/时间/耗时接 `--td-font-mono` + `tabular-nums` | 工单列表纵向对齐；截图对比 |
| 0-4 | 圆角标度改 Apple 尺度（8 / 12 / 18 / 5） | 全站抽查 6 个页面截图 |
| 0-5 | 语义色换 Apple 系统色 | `make palette-check` 六项全过，否则调明度/彩度重跑；**不过不合并** |
| 0-6 | 暗色令牌决策：现行 `#0f1114` vs macOS 分层（纯黑 + `#1c1c1e`） | 工单列表两套暗色各出一张截图实测光晕，选一套，另一套删干净 |

**P0 出口**：`make lint` + `npm run lint` + `npm run build` 全过，
六个代表页（工单列表 / 工单详情 / 项目列表 / 告警列表 / 报表 / 系统设置）
亮暗各一张截图，与改造前逐张对比。

## P5 · 打磨

- 三态齐备逐组件核对（hover / `:focus-visible` / `:active`）
- 响应式：窄屏侧边栏收起、表格容器内横向滚动、页面主体不横向滚动
- 可访问性：键盘可达、`aria-label`、`prefers-reduced-motion`、暗色对比度

## 每个阶段的收尾动作

1. `make lint` + `cd web && npm run lint` + `npm run build`
2. 改动页面亮暗各一张截图，与改造前对比
3. 分阶段提交，commit 信息用中文，不带 AI 署名
4. 有令牌变更时，同步更新 CLAUDE.md §3 —— 文档和代码不许漂移
